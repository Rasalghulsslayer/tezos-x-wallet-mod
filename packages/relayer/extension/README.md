# TezosX Relayer — Browser Extension

> **Superseded proof of concept.** This Temple-backed extension was the first
> injection vehicle for the relayer and is kept for reference only. The
> supported extension is **[`@tezosx/wallet`](../../wallet/)** — a standalone
> MV3 wallet with its own signer, approval flow, and security hardening. Its
> `manifest.json` version is frozen at **0.4.1** and is decoupled from the
> `@tezosx/relayer` package version.

Chrome/Brave extension (Manifest V3) that automatically injects `window.ethereum` on all pages, routing transactions to Temple Wallet via the Tezos X NAC gateway.

Unlike the IIFE version (manually injected script), the extension is active as soon as the page loads, with no changes required on the dApp side.

## Prerequisites

- **Temple Wallet** installed in the browser
- **Tezos X Previewnet** network configured in Temple:
  - Name: `Tezos X Previewnet`
  - RPC URL: `https://michelson.previewnet.tezosx.nomadic-labs.com`

## Build

```bash
# From the repo root (tezos-x-wallet/)
npm install
npm run build:ext          # outputs the bundles to extension/dist/
```

After modifying the sources, re-run the build then click **⟳ Reload**
on the browser's extension management page.

## Installation (developer mode)

Build first (above) — the `manifest.json` at this folder's root references the
compiled `dist/` bundles.

### Chrome / Brave

1. Open `chrome://extensions` (or `brave://extensions`)
2. Enable **Developer mode** (top right corner)
3. Click **Load unpacked**
4. Select this folder (`packages/relayer/extension/`)

> **Brave only**: to avoid a conflict with Brave Wallet, go to
> `brave://settings/web3` → *Default wallet* → select **None** or **Extensions**.

### Firefox

Firefox supports Manifest V3 since Firefox 109. The process is the same via `about:debugging` → *This Firefox* → *Load Temporary Add-on* → select `manifest.json`.

## Architecture

```
extension/
├── manifest.json          Manifest V3 (version frozen at 0.4.1)
├── popup.html             Popup UI (connected sites)
├── src/
│   ├── messages.ts        Shared types across contexts
│   ├── injected.ts        window.ethereum + EIP-6963 (MAIN world)
│   ├── content.ts         Script injection + page → background bridge
│   ├── background.ts      Service worker: session storage
│   └── popup.tsx          Connected sites display and disconnect (React)
└── dist/                  Compiled bundles (generated by build:ext)
```

### Communication flow

```
Page (window.ethereum)
  │  postMessage  TEZOSX_SESSION_UPDATE
  ▼
content.ts  (isolated world)
  │  chrome.runtime.sendMessage
  ▼
background.ts  (service worker)
  │  chrome.storage.local
  ▼
popup.tsx  (user interface)
```

The business logic (Beacon SDK, RPC calls, Micheline construction) runs
entirely inside the injected script — in the same JavaScript context as the page.
This avoids loading the Beacon SDK into the service worker (localStorage incompatibility).

### Per-origin sender guard

The service worker validates every message sender: it accepts messages only
from the extension's own contexts, and a page's content script may read or
mutate the stored session **for its own web origin only**. The popup, as
trusted first-party UI, may act on any origin. This closes the path where an
arbitrary page's content script could read or tamper with the whole session
map (added in relayer 0.7.0).

## Usage from a dApp

The API is identical to the IIFE version — no changes required on the dApp side.

```javascript
// Connect
const accounts = await window.ethereum.request({ method: 'eth_requestAccounts' });

// Send transaction
const txHash = await window.ethereum.request({
  method: 'eth_sendTransaction',
  params: [{ to: '0x...', value: '0x0', data: '0x...' }],
});

// Associated Tezos address (custom method)
const [tz1] = await window.ethereum.request({ method: 'tez_getAccounts' });
```

The extension also announces the provider via **EIP-6963**, making it
compatible with wagmi v2, RainbowKit, and ConnectKit without any additional configuration.
